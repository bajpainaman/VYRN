# VYRN L1 custody and bridge contract

The Ethereum L1 contract of CHAIN mode: spec/09-chain.md §6 (custody and the bridge), the L1 side of
§7 (forced inclusion), REQ-CHN-6 in spec/02-requirements.md, and B-CHN-4 (the `escapeClaim` gas
report). spec/11-build.md §1.2 gives Solidity no place in the tree, so the Foundry project lives in
`contracts/` at the repository root.

This README describes the interface for anyone who builds against the bridge: relayers, guardian
processes, wallets, and the Rust `vyrn-chain` crate. `src/IVyrnBridge.sol` is the ABI. `vectors/`
holds fixed-input digests, signatures and proofs that were computed **without** the contract, so
another implementation can check itself against them.

```sh
forge fmt --check && forge build && forge test          # in contracts/
forge test --gas-report                                  # B-CHN-4
```

| `script/gen_*.{py,cjs}` | The vector generators. Each one documents how to run it |

## Roles and keys (09 §2.2)

| Role | Key | Does |
|---|---|---|
| Bridge key BK_i, 5 of them | secp256k1 in an HSM | Signs `Post`, `Unpause` and `SignerSet` (EIP-712). 4 of 5 are needed |
| Guardian key GK_i, 5 of them | secp256k1 held online | Sends `veto`, `vetoRotation` and `pause` as a transaction. One guardian is enough |
| Relayer | anyone | Submits signed posts, unpauses, rotations and claims. Has no power of its own |
| User | anyone | `deposit`, `claim` (paid to `recipient`), `escapeClaim` (paid to `exit_address`), `refundDeposit` (paid to the depositor) |

A signer set is 5 distinct BKs and 5 distinct GKs in OpIdx order, numbered by `rotationNo`, and
genesis is 0. `signerSet(rot)` returns the set with that number, and `currentRotation()` names the active one.

## Typed data (EIP-712)

Domain: `{name: "VYRN", version: "1", chainId: <L1 chain id>, verifyingContract: <bridge>}`, the
same domain as secp256k1 transactions (09 §4.4). When the L1 chain id changes after a fork, the
contract recomputes the domain separator.

```
Post(uint64 postNo,uint32 chainId,bytes32 prevPost,bytes32 commit,bytes32 smtRoot,uint64 depositNonce,bytes32 wdRoot,uint32 wdCount,uint256[] wdTotals)
Unpause(uint64 pauseNo)
SignerSet(uint64 rotationNo,address[] bridgeKeys,address[] guardianKeys)
```

- `Post.prevPost` holds the EIP-712 **struct hash** of post `postNo − 1`, which chains the posts the
  way 09 §6.2 does. L1 does not check it, and guardians do (09 §6.5).
- `Post.wdTotals` has one entry per asset, in `assets()` order.
- A signature is 65 bytes, `r ‖ s ‖ v`, with `v` ∈ {27, 28} and low `s` (EIP-2). The contract
  rejects a whole set when any signature is malformed, made by an unknown key, or repeated. It
  does not skip such a signature. A set counts as 4-of-5 when it holds ≥ 4 distinct keys of the
  active set.
- `Unpause.pauseNo` names the pause it ends, so signatures for one pause never end a later one.

## Withdrawal tree (keccak256, 09 §6.2)

`leaf = keccak256(bytes.concat(keccak256(abi.encode(uint64 wdId, address token, uint256 amount, address recipient))))`
with sorted-pair keccak256 nodes. This is OpenZeppelin `StandardMerkleTree` with types
`["uint64","address","uint256","address"]`, so the standard tooling produces roots and proofs. Each
`wdId` pays at most once across all posts, and the claims of a post never exceed its `wdTotals`.

## Leaf encoding (BLAKE3 SMT, 09 §9.3)

09 §9.3 does not fix the byte encoding of the leaf values. This contract proposes one, which the
`vyrn-chain` crate must use or replace through the spec. All integers are little-endian (01 §3):

```
AccountLeaf key   = BLAKE3(0x01 ‖ le32(account))
AccountLeaf value = [owner_kind] ‖ owner (32 B) ‖ le64(nonce) ‖ exit_address (20 B)
BalanceLeaf key   = BLAKE3(0x02 ‖ le32(account) ‖ le16(asset))
BalanceLeaf value = le128(free) ‖ le128(alloc_sum) ‖ le128(transit) ‖ le128(pending_unposted) ‖ le128(pending_posted)
leaf_hash = BLAKE3(derive_key("vyrn v1 smt leaf", key ‖ value))
node_hash = BLAKE3(derive_key("vyrn v1 smt node", left ‖ right))
```

Bit d of a key, where d = 0 is the most significant bit of byte 0, takes the right child at depth d.
Bit d of `bitmap`, counted the same way, is set iff the sibling at depth d is not empty. `siblings`
holds the non-empty siblings in increasing depth. An `owner` of kind 1 (an EVM address) sits
right-aligned in 32 bytes. `AssetId` is taken as u16 and `AccountId` as u32 (01 §3).

## Behaviour (09 §6)

| Path | Rule |
|---|---|
| Deposit | The token must be listed, `amount` > 0, `ownerKind` 0 (Ed25519) or 1 (an EVM address, high 12 bytes zero), and `owner` ≠ 0. Nonces start at 1. The amount received must equal `amount`, so fee-on-transfer and rebasing tokens are rejected. Confirmation policy: validators count only finalized L1 blocks (09 §6.3), which is off-chain |
| Post | `postNo` = last + 1, `chainId` matches, `wdTotals` has one entry per asset, `depositNonce` ≤ `depositCount`, and ≥ 4 BK signatures |
| Veto | Any active GK, while `now < acceptedAt + CHN_CHALLENGE_S` (3,600 s). The post stays vetoed. Later posts go ahead (09 §6.5) |
| Re-propose a vetoed number | Only the same post (same EIP-712 digest), with 5-of-5 at once, or 4-of-5 once `now ≥ vetoedAt + CHN_VETO_OVERRIDE_S` (259,200 s). A post accepted this way cannot be vetoed again |
| Claim | The post is accepted, `now ≥ acceptedAt + 3,600`, the proof is valid, the `wdId` is unpaid, and the post total holds. A claim pays as much of the unpaid amount as keeps the rolling 24 h outflow ≤ 10% (`CHN_BRIDGE_DAILY_CAP_BPS`). The rest stays claimable, and the caller claims again in a later window. It reverts `OverDailyCap` only when nothing can be paid |
| Pause | Any active GK. Blocks deposits, posts and claims. A new pause cancels a scheduled unpause |
| Unpause | ≥ 4 BK signatures over `Unpause(pauseNo)`. Takes effect `CHN_UNPAUSE_DELAY_S` (86,400 s) after the call |
| Rotation | ≥ 4 BK signatures over `SignerSet(active + 1, …)`, queued for `CHN_BRIDGE_ROTATE_S` (259,200 s). Any active GK may `vetoRotation` before then. A vetoed number can be queued again only with 5-of-5, which also makes it unvetoable. 5-of-5 on the first try also makes it unvetoable. Posts accepted earlier stay claimable |
| Escape | Anyone may call `enterEscape` once `now ≥ lastAcceptedAt + CHN_ESCAPE_S` (1,209,600 s). Escape is permanent. The escape post is the highest accepted post that is not vetoed. Calls resume in steps of 1,024 vetoed posts. Escape then blocks deposits, posts, pauses and rotations. Claims of accepted posts keep working, even while paused |
| escapeClaim | An AccountLeaf proof and a BalanceLeaf proof against the escape post's `smtRoot`. Pays `free + allocSum + transit + pendingUnposted` to `exit_address`, once per (account, asset) |
| refundDeposit | Escape mode, for a nonce in (`escapeDepositNonce`, `depositCount`], once. Pays the depositor |

**Forced inclusion (09 §7)** happens on the VYRN side: a `ForcedPacket` reaches the leaders on the
transaction path. The contract has no forced-inclusion entry point. Its share of censorship
resistance is the escape hatch. If the validators stop posting, for example to hold withdrawals,
anyone opens escape after 14 days and users exit against the last posted root
(`test_forcedExit_whenValidatorsCensorPosts`).

## Decisions where the spec is silent or differs

1. `escapeClaim` takes the AccountLeaf as well as the BalanceLeaf, plus one proof for each. 09 §6.2
   passes only the BalanceLeaf, but `exit_address` lives in the AccountLeaf (§9.3).
2. Unpause signs `Unpause(uint64 pauseNo)`. 09 names no message type for it.
3. Guardians veto a rotation through `vetoRotation(rotationNo)`. 09 §6.7 step 3 requires the veto,
   and §6.2 does not name the function.
4. In escape mode, `pause` no longer blocks claims, so a single guardian cannot freeze exits for
   good after the bridge is dead.
5. The SMT verifier is a separate stateless contract (`SMT()`), because the bridge with BLAKE3
   inlined is 33.5 kB, over the EIP-170 limit of 24,576 bytes.
6. The 24 h cap uses 25 hourly buckets, and the cap is 10% of (balance now + outflow in the window), rounded up so the last base units can leave.
   With this rounding the cap lets out up to one extra hour of outflow, which is conservative toward liveness.
